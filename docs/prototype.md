# FloorRush 프로토타입

FloorRush는 출근 시간대에 엘리베이터를 놓치지 않으려고 달리는 Unity 3D 1인칭 순발력 게임이다. 첫 프로토타입에서 검증할 것은 플레이어가 두 층을 보고 방향을 판단한 뒤, 엘리베이터가 떠나기 전에 호출 버튼까지 달려가 탑승할 수 있는지다.

## 플레이 흐름

1. 플레이어가 출발 지점에 나타나면 화면 **상단 중앙**에 `현재 위치는 {현재층}층, 목적지는 {목적층}층`을 표시한다. 현재층과 목적층은 서로 다르게 설정하고, 안내에는 정답 방향을 표시하지 않는다.
2. 플레이어는 1인칭으로 엘리베이터 앞까지 달려가 올라감·내려감 버튼 중 하나를 누른다. 목적층이 더 높으면 올라감, 더 낮으면 내려감이 정답이다. 버튼 앞에서만 호출할 수 있어야 한다.
3. 엘리베이터가 현재층을 떠나기 전에 올바른 버튼을 누르면 즉시 탑승 성공으로 처리한다. 첫 버전에서는 추가 탑승 조작을 요구하지 않는다. 잘못된 방향으로는 탑승할 수 없고, 호출에 성공하기 전에 엘리베이터가 떠나면 해당 시도는 실패한다.

## 스테이지와 공간

| 예정 스테이지 | 출발 지점 | 목적지 | 정답 |
| --- | --- | --- | --- |
| 아파트 출근길 | 1층보다 높은 층의 집 현관 | 아파트 1층 | 내려감 |
| 회사 출근길 | 회사 건물 로비 | 로비보다 높은 사무실 층 | 올라감 |

첫 구현은 기본 도형으로 만든 테스트 공간 하나를 공유한다. 현재층·목적층·출발 위치·엘리베이터가 떠나는 시간은 스테이지별로 조정할 수 있게 두고, 방향과 탑승 판정은 두 상황에서 같은 로직을 사용한다.

벽과 문은 Cube, 바닥은 Plane 등 Unity 내장 3D 도형만 사용한다. 외부 에셋을 제작하거나 가져오지 않는다. 실제 아파트·회사 맵 제작과 군중 행동 구현은 핵심 플레이를 검증한 뒤로 미룬다.

## 플레이 검증 기준

- **방향 판단** — 두 스테이지에서 상단 중앙의 한글과 층수가 제대로 보이고, 같은 테스트 공간에서도 정답이 각각 내려감과 올라감으로 바뀐다.
- **호출 거리와 시간** — 출발 지점에서 누르거나 반대 방향을 누르면 탑승하지 않는다. 버튼 앞에서 출발 직전에 정답을 누르면 성공하고, 엘리베이터가 떠난 뒤에는 같은 입력으로 성공할 수 없다.
- **재시도** — 실패 후 다시 시작하면 플레이어 위치, 층 안내, 남은 호출 시간, 직전 탑승 결과가 새 시도의 시작 상태로 돌아간다.

## 문서 갱신 규칙

- 현재 플레이 규칙은 이 파일에 반영한다. 이전 버전은 Git 이력에서 확인하고, 두 규칙을 동시에 비교하는 실험에만 별도 문서를 만든다.
- 규칙을 바꿀 때는 본문의 성공·실패 조건과 해당 플레이 검증 기준을 함께 고친다. 플레이 테스트 결과가 변경의 계기라면 아래 변경 기록에 이유를 한 줄 남긴다. 문구 수정이나 호출 거리 같은 단순 수치 조정은 Git 이력만으로 관리한다.
- 특정 빌드에서 테스트한 규칙을 보존하려면 그 빌드의 코드와 이 문서가 함께 들어 있는 커밋에 Git 태그를 붙인다.
