# FloorRush 프로토타입

FloorRush는 출근길에 닫히는 엘리베이터 문을 보고 달려가 호출 버튼을 누르는 Unity 3D 1인칭 게임이다. **프로토타입은 아파트 하행에 성공한 뒤 회사 상행까지 한 번에 이어서 플레이할 수 있을 때 완성된다.** 한 테스트 공간에서 층 안내를 읽고, 방향을 판단하고, 마감 직전에 버튼을 누르는 재미를 검증한다.

## 스테이지와 출발 신호

| 순서 | 출발 위치와 시점 | 화면 상단 중앙 안내 | 정답 버튼 | 패널까지 거리 / 호출 마감 |
| --- | --- | --- | --- | --- |
| 1. 아파트 | 집 현관 앞에서 복도를 바라본다. | 현재 위치는 8층, 목적지는 1층 | ▼ 내려감 | 약 12m / 시작 후 6초 |
| 2. 회사 | 건물 로비 입구에서 승강장 쪽을 바라본다. | 현재 위치는 1층, 목적지는 6층 | ▲ 올라감 | 약 16m / 시작 후 7초 |

아파트에서는 문이 닫힌 채 표시기가 11 → 10 → 9층으로 내려온다. 8층 도착 전까지 ▼를 한 번 누르면 호출이 접수된다. 승강기는 남은 거리를 내려와 8층에 정차하고, 문이 완전히 열리면 자동 탑승한다. 호출 없이 도착 시각을 넘기면 문을 열지 않고 7층으로 지나간다.

회사에서는 1층에 문이 열린 상태에서 시작한다. 마감 **2초 전**부터 두 문이 닫히기 시작한다. 문이 완전히 닫히는 순간이 마감이며, 승강기가 떠나면 표시기의 층수가 바뀐다. 플레이어는 숫자 카운트다운 없이 문과 표시기를 보고 출발을 알아차려야 한다.

레벨 디자인 시 SampleScene의 **Elevator Round**를 선택하고 Inspector에서 **Apartment** 또는 **Office**를 펼친다. 각 맵의 현재층, 목적층, 스폰 위치, 호출 마감 시간과 다음 값을 조정한다.

| 설정 | 아파트 기본값 | 회사 기본값 | 적용 방식 |
| --- | --- | --- | --- |
| 건물 최고층 / 하강 시작층 | 11층 / 11층 | 6층 / 1층 | 최고층은 현재층·목적층 이상이다. 하강 시작층은 현재층부터 최고층 사이로 제한한다. 현재층에서 시작하면 문을 열고 대기한다. |
| 승강기 정원 / 승객 최소~최대 | 4명 / 1~3명 | 4명 / 1~3명 | 플레이어 한 자리를 비우고 나머지 정원과 승객 자리 수 안에서 배치한다. 배치 구간의 길이와 최소 줄 간격으로 자리 수를 계산한다. |
| 복도 보행자 최소~최대 | 6~6명 | 6~6명 | 복도 배치 구간에서 한 줄에 최대 두 명씩 배치한다. 각 범위는 양 끝을 포함하며 0~0명으로 설정하면 아무도 배치하지 않는다. |

각 맵의 승강기 양옆과 복도 배치 구간은 부모 기준 로컬 Z 시작·끝 좌표와 최소 줄 간격으로 정한다. 복도에서는 인원에 맞춰 필요한 줄만 구간에 고르게 펼친다. 출발점과 호출 패널 앞은 구간 밖에 둔다. 기본 구간에는 승강기 양옆에 총 6명, 복도에 총 12명까지 설 수 있다. 맵별 정원과 배치 구간을 먼저 반영하고, 두 맵 중 필요한 최대 인원만큼 Awake에서 기존 자식에 부족한 Passenger 프리팹을 보충한다. 매 라운드에는 해당 맵의 범위에서 인원을 뽑아 필요한 사람만 활성화한다. 풀 크기를 늘리는 Inspector 변경은 Play Mode에 다시 진입하면 적용된다. 두 층 조합은 표의 값으로 고정한다. 거리와 마감 시간, 문 닫힘 예고 시간은 첫 테스트값이며 플레이해 보고 조정한다.

**승객 스폰 상한**은 승객 최대값, 정원에서 플레이어 한 자리를 뺀 수, 양옆에 실제로 설 수 있는 자리 수 중 가장 작은 값이다. 승객 최소값도 이 상한을 넘을 수 없다. 아파트 기본 배치 구간(Z 7.65~8.78m, 최소 줄 간격 0.55m)에는 한쪽에 세 명씩 총 여섯 명이 선다. 승객 11명을 배치하려면 플레이어를 포함한 정원이 최소 12명이어야 하고, 승강기 내부와 배치 구간 모두 한쪽에 여섯 줄이 들어갈 만큼 길어야 한다.

## 조작과 호출 판정

기본 설정에서 아파트와 회사 모두 라운드가 시작되면 승객 1~3명이 승강기 안에 이미 서 있다. 다시 시도하거나 스테이지를 전환할 때마다 승강기 양옆 배치 구간에서 최소 줄 간격을 지키는 자리를 무작위로 고른다. 승객은 그 라운드 동안 제자리에 서 있고, 문 중앙에서 승강기 안으로 이어지는 탑승 동선은 비워 둔다.

기본 설정에서 복도에는 세 구간에 두 사람씩 서 있다. 매 시도마다 각 구간의 왼쪽·가운데·오른쪽 중 두 곳에 사람을 배치하고, 연속한 구간은 서로 다른 쪽을 비운다. 사람에게 부딪히면 이동이 막히고 호출 마감 시간은 계속 흐른다. 옆으로 비켜 달려서 패널에 도착하면 평소처럼 호출할 수 있다.

`WASD`로 이동하고 마우스로 시점을 돌린다. 이동 중 `왼쪽 Shift`를 누르면 달린다. 호출하려면 화면 중앙 조준점을 승강장 패널의 ▲ 또는 ▼ 버튼에 맞추고 `E`를 한 번 누른다.

▲·▼ 표시는 승강장 버튼 앞면에서 읽을 수 있다. 탑승 후에는 닫힌 문과 승강기 벽이 바깥쪽 표시를 가린다.

| 상황 | 판정 |
| --- | --- |
| 마감 전, 버튼에서 2m 이내이고 조준선이 해당 버튼에 먼저 닿음 | `E`를 새로 누른 프레임에 판정한다. 목적층이 더 높으면 ▲, 더 낮으면 ▼가 정답이다. |
| 위 조건에서 정답을 누름 | 그 순간 성공을 확정한다. 아파트에서는 도착할 때까지 기다린다. 회사에서 닫히던 문은 현재 위치에서 다시 완전히 열린다. 문이 열리면 1인칭 시점으로 출입구를 지나 안에 들어가 돌아선 뒤 성공 화면을 보여준다. 이미 활짝 열려 있다면 바로 탑승 연출을 시작한다. |
| 위 조건에서 반대 버튼을 누름 | 즉시 실패. 이후 정답을 눌러도 결과가 바뀌지 않는다. |
| 마감 전, 거리가 2m를 초과하거나 조준선이 빗나가거나 벽에 막힘 | 입력을 무시하고 라운드를 계속한다. 키를 누른 채로 접근해도 호출되지 않는다. |
| 호출에 성공하기 전에 마감 시각에 도달함 | 엘리베이터를 놓친 것으로 처리한다. 마감 시각과 같거나 늦은 입력은 실패이며, 한 시도의 결과는 한 번만 확정한다. |

실패 화면에서 **다시 시도**를 누르면 같은 스테이지를 다시 시작한다. 아파트 성공 후 **다음 스테이지**를 누르면 회사로 이동한다. 회사 성공 후 **처음부터**를 누르면 아파트로 돌아간다. 새 시도마다 스폰 위치와 시점, 문, 마감 시각, 층 안내와 표시기, 결과 UI, 호출 입력 상태를 초기화한다.

## 구현 기준

- **씬과 환경** — Unity `6000.3.8f1`, 기존 URP와 Input System을 사용한다. 기존 `SampleScene`의 카메라와 조명을 재사용한다. Plane 바닥과 Cube 벽·문·패널로 한 공간을 구성하고 플레이어의 `CharacterController`로 충돌을 처리한다. 외부 에셋, 실제 아파트·회사 맵, 군중 시뮬레이션은 이번 범위에서 제외한다.
- **입력** — `Assets/InputSystem_Actions.inputactions`의 `Player` 맵에서 `Move`, `Look`, `Sprint`, `Interact`를 재사용한다. `Interact`에는 `Hold`가 설정되어 있으므로 호출은 길게 누르기 완료 시점 대신 키를 처음 누른 프레임을 기준으로 삼는다.
- **책임** — 플레이어는 이동과 조준을 처리하고 패널은 선택한 방향을 전달한다. 두 스테이지가 공유하는 라운드 관리자가 마감 시각과 성공·실패를 판정한다. 싱글톤은 씬에 하나인 라운드 관리자에만 적용한다. 문과 UI는 별도 타이머 없이 같은 라운드 상태를 표시한다.
- **에디터** — 에디터 조작에는 Codex의 Unity 플러그인과 CLI만 사용한다. 작업 전 프로젝트 루트에서 `unity status --project-path . --format json`으로 프로젝트 경로와 `ready` 상태를 확인한다. Unity AI Assistant는 사용하지 않는다.

## 기능별 구현과 직접 테스트

| 순서 | 기능 브랜치 | 사용자가 직접 확인할 절차 |
| --- | --- | --- |
| 1 | `feat/first-person-movement` | `SampleScene`에서 복도를 바라보고 걷다가 왼쪽 Shift로 패널까지 달린다. 마우스로 시점을 돌리고 벽을 향해 계속 이동해도 통과하지 않는지 확인한다. |
| 2 | `feat/elevator-call` | 아파트에서 ▼로 탑승한다. 별도 시도에서 ▲를 눌러 즉시 실패하고, 다시 시도한 뒤 아무 입력 없이 승강기가 8층을 지나가면 놓침을 확인한다. |
| 3 | `feat/commute-stages` | 아파트에서 ▼로 성공한 뒤 다음 스테이지를 선택한다. 회사 안내를 읽고 같은 패널의 ▲로 탑승한다. 처음부터를 눌러 아파트 시작 상태를 확인한다. |

각 기능은 `main`에서 분기하고, 독립적으로 검증할 수 있는 단위마다 한국어 명사형 제목으로 커밋한다. QA 결과와 직접 테스트 절차를 전달하고, 사용자가 직접 테스트한 뒤 승인하면 `main` 대상 PR을 생성한다. 수정 요청은 같은 브랜치에서 반영하고 다시 검증한다. 다음 기능은 이전 PR이 병합된 `main`에서 분기한다.

| Play Mode | 아파트에서 하강 중 ▼를 누르고 문과 표시기를 본다. 별도 시도에서 호출하지 않는다. | 호출 후에도 문이 닫힌 채 표시기가 내려오고 8층에 정차한다. 완전 개방 후 탑승한다. 미호출 시 문이 닫힌 채 7층과 놓침 결과가 표시된다. 재시도하면 11층에서 다시 시작한다. |

Play Mode 항목은 연결된 Unity 에디터에서 CLI로 재현한다. 기능별 QA 결과에는 콘솔 오류 확인 결과, 실제로 확인한 항목과 아직 검증하지 못한 항목을 구분해 적는다.

## 문서 갱신 규칙

- 현재 플레이 규칙은 이 파일에 반영한다. 이전 버전은 Git 이력에서 확인하고, 두 규칙을 동시에 비교하는 실험에만 별도 문서를 만든다.
- 규칙을 바꿀 때는 본문의 성공·실패 조건과 해당 플레이 검증 기준을 함께 고친다. 플레이 테스트 결과가 변경의 계기라면 아래 변경 기록에 이유를 한 줄 남긴다. 문구 수정이나 호출 거리 같은 단순 수치 조정은 Git 이력만으로 관리한다.
- 특정 빌드에서 테스트한 규칙을 보존하려면 그 빌드의 코드와 이 문서가 함께 들어 있는 커밋에 Git 태그를 붙인다.

## 플레이테스트 아이디어

이 목록에는 다음 플레이테스트에서 시험할 후보를 모은다. 관찰한 상황과 다음에 시험할 변경을 한 줄에 함께 적는다. 아이디어를 채택하면 해당 줄을 목록에서 빼고 본문의 플레이 규칙과 검증 기준에 반영한다. 플레이테스트 결과를 근거로 규칙을 바꿨다면 아래 변경 기록에 이유를 한 줄 남긴다.

<!-- 작성 예시: - 패널 앞에서 ▲와 ▼를 구별하는 데 시간이 걸렸다. 다음 테스트에서 버튼 간격을 넓혀 본다. -->

- 흰 점 조준점은 버튼에서 멀리 떨어져도 똑같이 보여 누를 수 있는 거리를 가늠하기 어렵다. 1인칭 팔과 손을 뻗어 버튼에 닿는 모습을 보여 주는 방식과, 평소에는 조준점을 숨겼다가 2m 이내에서 가려지지 않은 버튼을 겨냥했을 때만 표시하는 방식을 시험한다.
- `E`를 눌러도 어느 버튼이 반응했는지 알아보기 어렵다. 입력이 실제로 접수된 순간 누른 ▲ 또는 ▼ 버튼의 색이 바뀌거나 불빛이 켜지게 해, 플레이어가 그 자리에서 결과를 확인할 수 있는지 본다.
- 현재 두 스테이지는 같은 크기의 승강기를 쓴다. 스테이지마다 승강기 내부를 넓히거나 좁히고 정원도 늘리거나 줄여, 문이 열렸을 때 남은 자리를 알아보는 난이도가 어떻게 달라지는지 시험한다.
- 현재는 승객이 많아도 플레이어 한 자리가 남는다. 첫 승강기는 문을 열고 정원이 꽉 찬 모습을 처음부터 보여 준다. 달려가 붙잡으면 안의 승객들이 “다음 거 타세요!”라며 짜증을 내고 탑승할 수 없다. 플레이어가 만원을 알아보고 첫 차를 보낸 뒤 자리가 있는 다음 승강기에 타면 성공하는 스테이지를 시험한다.
- 현재 화면 상단 중앙에는 현재층과 목적층이 표시된다. 여기에 승강기 정원을 함께 안내하고, 플레이어가 문이 닫히기 전에 안에 보이는 승객을 세어 자기 자리까지 있는지 판단하게 한다. 예를 들어 정원 4명에 승객이 3명이면 타고 4명이면 보낸다. 스테이지마다 정원을 늘리거나 줄여 순발력과 수리 판단을 함께 시험한다.
- 아파트에서 하강 중인 승강기를 호출하면 시선이 ▼ 버튼에 고정돼 층 표시를 놓친다. `E`를 누른 직후 카메라가 문 위의 층 표시기로 부드럽게 향해 8층에 도착할 때까지 그곳을 바라보고, 도착하면 시선이 열리는 문으로 내려와 완전 개방 후 기존 1인칭 탑승 애니메이션으로 끊김 없이 이어지는 연출을 시험한다.
- 내 층에서 문이 열려 있고 안에 승객이 있을 때 “잡아 주세요!”라고 외치는 스킬을 시험한다. 승객이 무작위로 문을 잡아 주거나, 반대로 닫힘 버튼을 눌러 문을 더 빨리 닫게 해 본다.
- 탑승 후에는 목적층 버튼 상태에 따라 짧은 연출을 시험한다. 이미 눌려 있으면 가만히 서서 숨을 고르고, 아직 눌려 있지 않으면 직접 버튼을 누르는 애니메이션을 재생한다.
- 게임을 시작하면 첫 화면에서 바닥이 보였다. 시작 시 카메라를 눈높이에서 수평으로 맞추고, 마우스를 움직이기 전부터 복도 정면이 보이는지 확인한다.
- 복도에 배치된 사람들은 지금 제자리에 서 있다. 플레이어처럼 승강기를 타러 가거나, 승강기 반대 방향으로 걸어가거나, 집 현관 앞에서 문을 열고 들어가는 행동을 시험한다. 이동 경로에 걷기와 문 열기 애니메이션을 맞춘다.
